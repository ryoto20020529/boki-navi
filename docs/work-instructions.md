# 簿記合格ナビ 作業指示書（最上位モデル利用期間用）

最上位のAIモデルを使える期間は限られている。その間に、**精度が求められる作業**と**今後のミスを防ぐ仕組みづくり**を優先して片づける。
新しいセッションの最初に、この文書の全文と `AGENTS.md` を読ませること。

## 0. 前提（現状）
- サイト: https://boki-navi.vercel.app （Vercel。mainへのマージで自動公開）／リポジトリ: `ryoto20020529/boki-navi`
- 構成: `src/pages` `src/partials` `src/root` を編集 → `python3 tools/build.py` で直下のHTMLを生成（詳細は `AGENTS.md`）
- 公開ページ: トップ・`/boki`・`/acaschool`（法務3ページは手書き）
- 料金（オンライン／対面）: 3級 2,000／2,500、2級 2,600／3,100、1級 3,500／4,000、アカスク 4,000／4,500（税込・60分）
- 対面の対応エリア: 東京・埼玉・神奈川（対応できる場合・要相談）
- 講師は**依頼を受けてから**選ぶ。日商簿記は受講する級以上の資格保持者が担当（1級は1級保持者）。講師の実績や受講者の声はまだ存在しない
- フォーム: Web3Forms。届け先は `wasecpa.academy@gmail.com`（設定済み）
- 運営者は事業の初心者。**公開（mainへのマージ）は運営者の承認後。** 選択肢と推奨案の形で確認する

## 1. 絶対に守ること
1. 架空の実績・講師・受講者の声・合格率を作らない。
2. 試験の制度・日程・出題範囲などの**事実は、公式サイトで確認できるものだけ**書く。確認できなければ書かない。数字には出典を付ける。
3. 料金は全箇所を一致させる（一覧は `AGENTS.md`）。
4. 公開前に、デスクトップ（1280px）とスマホ（390px）で、横方向のはみ出しとJSエラーがないことを確認する。
5. 法律・税金の判断は断定しない。「一般的な整理」と明記し、専門家確認を促す。

## 2. 作業一覧（優先順）

### 優先A：精度が求められる作業（最上位モデルで行う価値が高い）

**A1. 全ページ総点検（監査レポート＋修正）**
- 対象: トップ・`/boki`・`/acaschool`・特商法・利用規約・プライバシーポリシー
- 観点: ①表示と実態のずれ（料金・講師・エリア・支払い） ②景品表示法・特商法・消費者契約法・個人情報保護法 ③SEO（title・description・見出し・内部リンク・構造化データの整合） ④アクセシビリティ（コントラスト・フォーカス・ラベル・`aria`） ⑤表示速度（Lighthouseで測定し、数値を記録）
- 成果物: `docs/audit-YYYYMMDD.md`（問題・重要度・対応）。重要度が高いものは同じ作業内で修正し、PRにまとめる

**A2. 自動チェックの仕組み（今後のミス防止）**
- `tools/check.py`（または Playwright）で、次を自動検査する:
  - 料金が `assets/site.js` の `PRICES` と全ページで一致している
  - FAQの本文と構造化データ（FAQPage）が一致している
  - 内部リンク切れがなく、`sitemap.xml` と実在ページが一致している
  - 各ページに title・description・canonical があり、H1が1つ
  - 「統計検定」「アクチュアリー」「最短○日」「必ず合格」など、使ってはいけない語が残っていない
  - 生成物が `tools/build.py` の出力と一致している（直接編集の検知）
- GitHub Actions で、PRごとに自動実行する。成功条件: 失敗するPRはマージできない旨を `AGENTS.md` に追記

**A3. 級別ページの新設（`/boki3` `/boki2` `/boki1`）**
- 目的: 「簿記2級 個別指導」「簿記2級 工業簿記 苦手」などの検索意図に個別に答える
- 各ページの内容: 対象者・出題範囲の要点（日本商工会議所の公式情報に基づく）・つまずきやすい論点と指導の進め方・料金・FAQ（5問以上）・相談導線
- 既存の `/boki` は総合ページとして残し、級別ページへ内部リンクする。`sitemap.xml`・フッター・関連コースを更新する

**A4. コラム（解説記事）の基盤と初期記事**
- `tools/build.py` を拡張し、`src/articles/*.md`（または `.html`）から `/column/<slug>` を生成できるようにする。記事には Article の構造化データ、パンくず、関連記事、相談導線を付ける
- 初期記事（案。事実確認が取れる範囲で、各1,500〜2,500字）:
  1. 簿記2級 工業簿記が苦手な人の勉強法
  2. 簿記3級の勉強時間の目安と進め方
  3. 簿記のネット試験と統一試験の違い
  4. 簿記2級の連結会計をやさしく整理する
  5. 早稲田会計研究科（アカスク）の志望理由書の書き方
- 執筆者は運営者名のみ。経歴・実績は書かない。試験情報は出典（公式サイトのURL）を明記する

**A5. 運営書類の整備**
- `docs/operations/` に、次のメールのテンプレートを作る: 初回返信（ヒアリング）／受講申込確認（契約）／請求／入金確認／講師への業務委託条件の通知
- 受講申込確認メールには、受講者名・コース・日時・形式・担当講師・料金・支払期限・キャンセル規定・規約URL・未成年の保護者同意を入れる
- 売上・経費・講師報酬の管理表（CSVまたはスプレッドシート用の列定義）と、初めて請求するまでのチェックリストを作る
- 税務・法務は「一般的な整理」であることを明記する

### 優先B：効果は大きいが、運営者の判断や準備が先に必要

**B1. 独自ドメインへの切り替え**（運営者がドメインを取得し、Vercelに追加してから）
- `tools/build.py` の `SITE` を変更して再ビルド。旧URL（`boki-navi.vercel.app`）から新URLへ301リダイレクトを設定。Search Consoleのプロパティ追加手順を `docs/` に書く

**B2. 講師募集ページ（`/recruit`）**（報酬水準と募集条件を運営者が決めてから）
- 講師は依頼後に探す運用のため、「早稲田会計研究科の院生・日商簿記の資格保持者」向けの募集ページを作る。報酬は運営者が決めた数字のみ載せる。応募フォームのコース選択肢は講師用に別にする

**B3. アクセス解析の導入**（運営者の承認後）
- Cookieを使わない解析（例：Cloudflare Web Analytics）を候補に、導入案を比較して推奨を出す。導入する場合は、プライバシーポリシーを同時に更新する

**B4. フォームの強化**
- スパム対策（Web3Formsの対策機能）の有効化手順、送信後の自動返信（有料機能の要否）、返信漏れ防止の運用案を、選択肢と推奨案で提示する

## 3. 運営者（人間）が先にやること
- 開業届・青色申告承認申請書の提出
- 事業用の入金口座の決定
- 講師の報酬水準の決定（B2の前提）
- 独自ドメインの取得（B1の前提）
- 載せてよい実績・受講者の声があれば、本人の了承を取って提供する

## 4. 進め方
1. A1 → A2 の順に実施する（以降の作業の土台になる）
2. A3〜A5 は、A2の自動チェックが動いてから進め、PRは作業ごとに分ける
3. PRごとに「確認したこと（スクリーンショット・数値）」を書く
4. 運営者への報告は、変更点の要約と「承認依頼（案A/B/C＋推奨）」の形で行う
